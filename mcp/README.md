# Bullwatt MCP server

The Bullwatt MCP server gives an AI assistant the context needed to create a training session without implementing a sports-generation engine on the server. The client model reads the real Bullwatt format and examples, generates JSON itself, then uses deterministic validation and safe storage.

The source catalog remains `../trainings/catalog/*.json`. `../trainings/trainings.json` is an aggregate generated by the existing `training_builder.php`; the MCP server reads source files directly and also reads `../trainings/generated/*.json`.

## Requirements and installation

- PHP 8.1 or later with `fileinfo`.
- Composer.
- The existing Bullwatt Docker setup for the HTTP transport.

From the repository root:

```sh
composer install --working-dir=mcp
docker compose up
```

The Streamable HTTP endpoint is then available at `http://localhost:8000/mcp/index.php`. It accepts only localhost host/origin values and is intentionally unauthenticated for local use.

The STDIO transport can be launched with local PHP:

```sh
php mcp/server.php
```

or inside the running container:

```sh
docker compose exec -T php-apache php /var/www/html/mcp/server.php
```

## Client configuration

For a client supporting Streamable HTTP:

```json
{
  "mcpServers": {
    "bullwatt": {
      "url": "http://localhost:8000/mcp/index.php"
    }
  }
}
```

For a local client that starts STDIO processes, replace the absolute paths for the current machine:

```json
{
  "mcpServers": {
    "bullwatt": {
      "command": "php",
      "args": ["C:/absolute/path/to/bullwatt/mcp/server.php"]
    }
  }
}
```

## Resources

- `bullwatt://training-format`: the existing human documentation, technical chronology rules, canonical JSON Schema, and a complete example.
- `bullwatt://trainings`: catalog summaries with duration, phase count, min/max FTP ratio, and duration-weighted average FTP ratio.
- `bullwatt://trainings/{id}`: one complete source session. An unknown id produces an MCP resource-not-found error.
- `bullwatt://generation-guidelines`: instructions the client model must follow.

No tags or categories are returned because the source format currently defines none.

## Tools

### `search_trainings`

All arguments are optional: `query`, `duration_min`, `duration_max`, `min_intensity`, `max_intensity`, `phase_count`, and `max_results` (1 to 50). Every query token must occur in the normalized id, name, description, source, or phase notes. Numeric filters are deterministic; `min_intensity` constrains the observed minimum and `max_intensity` constrains the observed maximum.

### `validate_training`

Takes `{ "training": { ... } }` and returns `valid`, blocking `errors`, non-blocking `warnings`, and metrics. The canonical generator format is strict:

- integer seconds and numeric JSON FTP ratios;
- first phase at zero and strictly increasing starts;
- active starts before the total duration;
- an optional final, zero-length end marker at exactly the total duration;
- a `units` object with `time: "seconds"` and `ftp_ratio: "number"` or `ftp_ratio: "ftp_ratio"`;
- each phase intensity stored in the `ftp_ratio` field (the legacy `value` field is rejected);
- no unknown fields;
- duration from 1 to 86400 seconds and ratio from 0 to 10.

The 10× FTP ceiling is a technical compatibility bound, not sporting advice. It covers the historical ramp-test data. Historical numeric strings and legacy unit labels remain readable but are rejected for newly generated sessions.

### `save_training`

Takes `{ "training": { ... }, "overwrite": false }`. The tool validates again, rejects invalid data, rejects an id already present in either catalog, and never supports overwrite mode. A valid session receives a cryptographically random id such as `generated-a8...`, is written atomically to `trainings/generated/<random-id>.json`, and returns that logical path.

The supplied id must still be a safe slug before it is replaced, preventing traversal input from reaching filesystem operations. The output directory is fixed by the server and no caller-supplied path is used.

## Prompt and generation example

The `generate_bullwatt_training` prompt accepts an optional `request` string. It instructs the model to:

1. Read the format and guidelines.
2. Search for similar sessions and read relevant complete resources.
3. Generate Bullwatt JSON directly in the client model.
4. Call `validate_training` and correct all blocking errors.
5. Present the JSON and a readable summary.
6. Call `save_training` only after explicit user approval.

For example, for “45 minutes, three eight-minute threshold blocks, three-minute recoveries, maximum 100% FTP,” the model should inspect threshold examples, calculate a 2700-second timeline, emit numeric `ftp_ratio` phases, validate, and only then offer to save. The MCP server does not generate or silently adjust the sports plan.

## Tests

Run the automated suite from the repository root:

```sh
docker compose exec -T php-apache php /var/www/html/mcp/tests/run.php
```

or with local PHP:

```sh
composer test --working-dir=mcp
```

The suite uses real catalog fixtures and covers resources, unknown ids, lexical and numeric search filters, result limits, validation rules and metrics, randomized atomic saving, collision/overwrite refusal, path traversal, catalog preservation, schema parsing, and server construction.

## Security and operational limits

- HTTP is bound by the project Docker port and protected against non-local Host/Origin values, but it has no authentication. Do not expose it publicly without a trusted reverse proxy, TLS, authentication, rate limiting, and an explicit host allowlist.
- Generated files are local and ignored by Git. There is no catalog index mutation and no arbitrary path parameter.
- Search is lexical only; it has no semantic embeddings, external service, or AI call.
- Validation ensures technical Bullwatt compatibility, not medical or coaching suitability.
- File-backed MCP sessions suit a single local Apache instance. A scaled deployment would need shared session storage.
